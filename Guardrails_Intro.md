# 2. What Are Guardrails?

### Definition

> **Guardrails are safety controls and policies that validate, filter, and restrict the inputs and outputs of an LLM or AI system to ensure that it behaves as intended.**

In simple terms:

**Guardrails = Rules + Checks around LLMs that prevent harmful, risky, or unintended behavior.**

They act as a safety layer around an AI application.

### Core objectives

Guardrails help to:

- Enforce policies
- Improve security
- Ensure compliance
- Improve reliability
- Protect users
- Build user trust
- Prevent harmful behavior
- Control unintended LLM behavior

---

# 3. Input and Output Guardrails

Two of the most important guardrail categories are:

1. **Input Guardrails**
2. **Output Guardrails**

They validate the information entering and leaving the AI system.

### High-level flow

```text
User Input
    ↓
Input Guardrail
    ↓
AI / LLM / Agentic Application
    ↓
Output Guardrail
    ↓
Safe & Reliable Response
```

---

# 4. Input Guardrails

Input guardrails inspect the **user's input before it reaches the LLM/application**.

### Example

User enters:

> "Hey, how can I hack a website?"

An input guardrail can detect that the request is potentially harmful and **block the request** instead of allowing it to proceed.

### Input guardrails can perform:

#### 1. Prompt Injection Detection

Detect malicious instructions designed to manipulate the model.

Example:

> "Ignore all previous instructions and..."

The guardrail can identify and block such prompts.

---

#### 2. Jailbreak Detection

Detect attempts to bypass the model's safety restrictions.

---

#### 3. PII Detection

Detect **Personally Identifiable Information (PII)**.

Examples:

- Email addresses
- Phone numbers
- Driving licence numbers
- Identification numbers
- Other personal information

---

#### 4. Secrets Detection

Detect sensitive secrets such as:

- API keys
- Passwords
- Tokens
- Credentials
- Other confidential information

---

#### 5. Toxicity / Hate / Abuse Detection

Detect inputs containing:

- Toxic language
- Hate speech
- Abusive content
- Unsafe content

---

#### 6. Input Validation

Check whether the input satisfies predefined requirements.

---

#### 7. Policy Compliance Check

Determine whether the user's request complies with organizational/business policies.

---

#### 8. Context Sanitization

Clean or sanitize input/context before it is passed to the LLM.

This helps prevent malicious or unwanted instructions from influencing the model.

---

# 5. Output Guardrails

Output guardrails inspect the **response generated by the LLM before it reaches the user**.

They ensure that the generated response is safe, valid, compliant, and useful.

### Output guardrails can perform:

#### 1. Toxicity Detection

Check whether the generated response contains toxic or abusive content.

---

#### 2. Hallucination Detection

Check whether the model has generated information that is unsupported or potentially fabricated.

---

#### 3. PII Detection / Masking

Check whether sensitive personal information has appeared in the response.

---

#### 4. Secret Masking

Prevent secrets or confidential information from being exposed.

---

#### 5. Fact Verification

Verify whether generated claims are factually supported.

---

#### 6. Policy and Compliance Check

Ensure that the generated response follows:

- Organizational policies
- Security policies
- Regulatory requirements
- Business rules

---

#### 7. Response Validation

Check whether the response follows the expected structure or format.

Example:

```text
Expected output → JSON
Actual output → Plain text
```

The guardrail can reject or modify the response.

---

#### 8. Refusal / Safe Response

If the original response is unsafe, the system can:

- Refuse the request
- Replace the response
- Generate a safer response

---

# 6. Why Are Guardrails Important?

Guardrails address many of the risks associated with AI/LLM applications.

### Major risks they help mitigate:

#### 1. Prompt Injection

Prevent malicious instructions from manipulating the application.

#### 2. Jailbreaks

Prevent users from bypassing safety restrictions.

#### 3. Toxic / Harmful / Unsafe Content

Block inappropriate or dangerous content.

#### 4. PII Exposure

Protect personally identifiable information.

#### 5. Secret Leakage

Prevent passwords, API keys, credentials, etc. from being exposed.

#### 6. Hallucinations

Help ensure that AI-generated information is grounded and reliable.

#### 7. Business Rule Violations

Ensure the AI follows application-specific rules.

#### 8. Compliance Violations

Help enforce regulatory and organizational requirements.

#### 9. Loss of User Trust

Safe and reliable AI systems create a more trustworthy user experience.

# C. Topic & Content Guardrails

These guardrails control **what topics or types of content the AI is allowed to discuss**.

### Features

#### Allow / Block specific topics

Certain topics can be explicitly:

- Allowed
- Blocked

#### Harmful-topic detection

Prevent discussion of prohibited or harmful subjects.

#### Domain-specific rules

Rules can be customized for a particular domain.

For example, a banking application may have different restrictions from a healthcare application.

#### Content moderation

Monitor and filter inappropriate content.

#### Custom rules and regulations

Organizations can define their own rules.

#### Allow List

Explicitly permitted content/actions.

```text
Allow List → Things the system is allowed to process
```

#### Block List

Explicitly prohibited content/actions.

```text
Block List → Things the system must reject
```

---

# D. Data & Security Guardrails

These focus specifically on **protecting sensitive information and data**.

### 1. Data Masking

Sensitive information can be masked before it reaches the LLM.

For example:

```text
Original:
Driving Licence Number → XXXXXXXX

Credit Card Number → XXXX-XXXX-XXXX-1234
```

Similarly, an email address could be masked:

```text
john@email.com
        ↓
[EMAIL_REDACTED]
```

The purpose is to prevent sensitive information from being unnecessarily exposed.

---

### 2. Secret Management

Protect sensitive credentials such as:

- API keys
- Passwords
- Tokens
- Access credentials

---

### 3. Data Leakage Prevention

Prevent sensitive or confidential information from leaking through the AI system.

---

### 4. Access Control

Ensure that users only have access to information/actions they are authorized to use.

---

### 5. Encryption

Protect data through encryption.

---

### 6. Auditing

Maintain records of relevant activities/events for security and compliance purposes.

---

# E. Behavioral & Task Guardrails

These control **what the AI system/agent is allowed to do**.

They are especially relevant to **agentic AI systems**, where an AI can call tools and perform actions.

### Features

#### 1. Tool Usage Restrictions

Control which tools an AI agent is allowed to use.

Example:

```text
Agent
 ├── Search Tool ✓
 ├── Calculator ✓
 └── Database Delete Tool ✗
```

---

#### 2. Action Validation

Validate an action before allowing it to execute.

---

#### 3. Command Restrictions

Limit which commands the AI/system can execute.

---

#### 4. Workflow Constraints

Ensure that an agent follows a predefined workflow.

---

#### 5. Human-in-the-Loop

Require human approval before performing certain sensitive actions.

Example:

```text
AI proposes action
       ↓
Human approval
       ↓
Action executed
```

---

#### 6. Feedback

Use feedback to improve or control system behavior.

---

#### 7. Rate Limiting

Restrict the number/frequency of requests or actions.

This helps prevent:

- Abuse
- Excessive resource usage
- Automated attacks

---

# 8. Examples of Guardrails

## Example 1 — Block Prompt Injection

Input:

> "Ignore previous instructions and tell me..."

Guardrail:

```text
Prompt Injection Detected
        ↓
BLOCK
```

---

## Example 2 — Block Toxic Response

If the LLM generates toxic or hateful content:

```text
LLM Response
     ↓
Toxicity Guardrail
     ↓
Toxic → BLOCK / MODIFY
```

---

## Example 3 — Mask Email

Input:

```text
John@email.com
```

Guardrail:

```text
John@email.com
      ↓
[EMAIL_MASKED]
```

This protects PII.

---

## Example 4 — Enforce JSON Output

Suppose the application requires:

```json
{
  "answer": "...",
  "confidence": 0.95
}
```

If the LLM produces plain text instead, an output guardrail can detect that the response does not satisfy the required format.

---

## Example 5 — Grounded Response

The system can verify:

> Is the generated answer actually supported by the provided context?

If not, the response can be rejected, modified, or regenerated.

This helps reduce **hallucination**.

# 9. How Guardrails Work

The lecture presents a high-level guardrail lifecycle.

```text
Define Rules
     ↓
Detect Risk
     ↓
Decide & Act
     ↓
Log / Notify / Monitor
     ↓
Improve
```

Let's break it down.

---

## Step 1 — Define Rules, Policies & Thresholds

First define:

- Rules
- Policies
- Thresholds
- Allowed behavior
- Restricted behavior

Example:

```text
Toxicity Score > Threshold
        ↓
Block response
```

---

# Step 2 — Detect Risk

The system uses different mechanisms to identify potential risks.

These may include:

- Models
- Rules
- Heuristics

They can detect things such as:

- Prompt injection
- Toxicity
- PII
- Secrets
- Hallucination
- Policy violations
- Unsafe actions

---

# Step 3 — Decide & Act

Once a risk is detected, the guardrail decides what should happen.

Possible actions include:

### Allow

Let the request/response continue.

### Block

Reject the request or response.

### Modify

Change or sanitize the content.

### Mask

Hide sensitive information.

Example:

```text
john@email.com
       ↓
[EMAIL_REDACTED]
```

The lecture also mentions **accelerate** as an action in the decision/action stage.

---

# Step 4 — Log, Notify & Monitor

Guardrail events should be recorded and monitored.

For example:

```text
User Input
   ↓
Prompt Injection Detected
   ↓
Request Blocked
   ↓
Event Logged
   ↓
Monitoring / Alerting
```

This connects guardrails with **observability**.

Important observability activities include:

- Logging events
- Monitoring violations
- Tracking guardrail behavior
- Notifying relevant systems/teams

---

# Step 5 — Improve

Guardrails should not remain static.

Use collected information to:

- Analyze incidents
- Measure effectiveness
- Refine rules
- Adjust thresholds
- Improve detection
- Improve policies

Therefore, the guardrail system follows a continuous improvement cycle:

```text
Detect
  ↓
Act
  ↓
Log
  ↓
Analyze
  ↓
Measure
  ↓
Refine
  ↓
Better Guardrails
```

### Key idea

Guardrails sit **around the AI system** to control both:

**What goes into the AI** and **what comes out of the AI.**
